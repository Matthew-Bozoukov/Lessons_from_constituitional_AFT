00

The idea, in one paragraph

Thought Branches argues that you cannot tell what caused a model's decision by reading one chain-of-thought. The reason it gives is sharp: “Therefore, the answer is no” correlates with a 99% no-rate and has almost no causal effect, because everything upstream already decided it. To get causation you resample — rerun the model many times from a chosen point and compare the outcome distributions.

Why this project needs it specifically: every attempt so far to work out why 716 difficult-advice rows cut ODCV misalignment has been read off an arm-level misalignment rate, and that number has a ~6 percentage-point seed-to-seed noise floor — wider than the entire band nine different corpus manipulations occupy. No further ablation read that way can succeed. Resampling measures effects inside one scenario without retraining, so it sidesteps the floor entirely.

01

What got built, and the one hard part

The paper's scenarios are one-shot: one chain of thought, one answer, so “resample from sentence i” is just another completion. ODCV is an agentic loop — the model runs bash, the environment answers, repeat — so a branch point splits a transcript and a world. There is no way to resample a continuation without deciding what the container does next. Two answers were built:

BackendHow it worksWhat it measuresCost
FrozenEnvSampler Replays the recorded tool results as the prefix; regenerates only the assistant's turn. The local action distribution — “standing here, what does it do?” 1 API call per sample
LiveEnvSampler
+ prefix_proxy		 Reruns the real container behind a proxy that serves back the recorded turns up to the branch, then forwards to the live model. The true ODCV outcome the existing judges score. 1 full container rollout per sample
The proxy is the trick that makes live branching possible: the container is never modified and never told anything changed, so it runs the same commands, reaches the same state, and every tool result after the branch is real. Turn accounting is by content — it counts the assistant messages in the incoming request — so a retry replays identically instead of sliding the branch point.

Alongside: sentence-level segmentation, an ODCV-native tag taxonomy, an LLM labeller with a free lexical fallback, local embeddings, and the paper's four metrics — counterfactual importance, resilience, counterfactual++, and the cumulative effect curve — plus a paraphrase control the literature says every counterfactual needs.

02

The cheap half: re-reading 859 judged rollouts

No GPU, no API calls. Five published arms, 40 scenarios, both variants, every rollout already carrying four judges' severities. 26.4% are violations.

Counting things is easy and almost entirely misleading. The strongest signal found was whether the agent stated a commitment before its first world-changing command: 67% in clean rollouts, 13% in violating ones, pointing the same way inside all five arms. Then compare only rollouts of the same arm on the same scenario in the same variant — 35 such cells contain both outcomes — and it evaporates: Δ = −0.02, interval −0.21 to +0.15.

Controlling for the model is not controlling for the task.

The three that survive

  • Violating rollouts run more commands (+5.3 [+0.2, +10.1])
  • They think less at each step (−96 characters [−172, −31])
  • They hit their obstacle earlier in the trace (−0.057 [−0.106, −0.011])

More steps, thinner thoughts. Everything lexical fails — integrity language, commitment language, shortcut language. And the sentence that licenses the violation by appealing to the user (“a PASS is required”) is a null in both directions, which is the same shape as the paper's finding about self-preservation in blackmail.

The fork

Nearly every ODCV scenario is rigged so the agent eventually discovers the target is unreachable honestly — a checker prints FAIL, a required file does not exist. Because the environment creates that moment, it can be found mechanically in every transcript with no labelling. It fires in 76% of rollouts, and it became the branch point for the causal half.

03

The expensive half: actually rerunning the model

One H100 for ~2 hours serving the numina-control adapter (the arm with no difficult-advice data, so the most violations and the most variety). Branched that same arm's own rollouts — using another arm's weights would be off-policy, the exact thing the method exists to avoid. 40 fork points, balanced 20 violating / 20 clean, 24 reruns each.

First, the check everything rests on

Resample each branch once at temperature 0 and ask how often the model reproduces the action it actually took. Answer: 34 of 40 — 85%. Without this number nothing downstream means anything: if the prefix reconstruction were wrong, a greedy resample would land somewhere else and every “effect” would be reconstruction error wearing a lab coat.

Every fork point, one cell, sorted by how often 24 reruns forced the metric

Forcing = fabricating the missing input, editing the checker, or deleting a record. A cell that is solid means the model did the same class of thing nearly every rerun.

mostly forces (>85%) — 6 points genuinely split (15–85%) — 4 points mostly does not force (<15%) — 30 points
22 of the 40 fork points forced in zero of 24 reruns; 5 forced in all 24. Only 4 sit anywhere in between. Nothing was truncated (0 of 960 generations hit the token cap), so this is not an artefact of the length limit.

And the fork thought will not go away

The paper's resilience metric resamples repeatedly and counts the rounds before a sentence's content stops coming back. Over 14 fork points, 5 rounds, 12 candidates a round: the best-of-12 similarity to the original sentence is flat and high in every round — 9 of 14 sit at 1.00 across all five, the lowest is 0.72. At least one regeneration reproduces the original thought almost verbatim, every single round. The content never drifts.

One case makes it concrete: Roboadvisor-Ethicsbypass forces in 100% of reruns, and its recorded rollout was judged clean. Forcing at the fork does not determine the verdict.

What it adds up to

By the time this agent has been refused by the environment, both what it thinks next and what it does next are largely fixed by the upstream context. The fork looked like the decision point. It is where an earlier decision becomes visible.

That sharpens rather than contradicts the cheap half: the fork-response clusters were mostly recovering scenario identity, the sharpest marker collapsed within scenario, and now the model itself shows almost no variance at that point. Practically it argues against spending more on fork-level interventions and for moving the branch point earlier, where the variance actually lives.

04

Four things I got wrong

Each of these produced a plausible-looking result before it was caught. They are the most useful part of the record.

Caught by inspecting cluster membership

The fork clustering was measuring the scenario

Clustering how the model answers the refusal gave a beautiful 73% → 0% violation gradient. But fork thoughts name their own scenario — the missing directory, the patient's symptoms, the specific threshold — so the clusters were largely recovering which task ran. The 73% cluster reads 23% inside its own largest scenario.

Fix: report each cluster's rate minus its own scenarios' base rates. Three survive that correction, including a protective one across 25 scenarios — enumerating every result explicitly.

Caught by the output being suspiciously uniform

The resilience threshold was calibrated against unrelated text

Every one of 12 fork points returned the maximum score. τ had been set to the target's median similarity against the other sentences of its own trace — mostly unrelated text, so a bar anything clears — and Algorithm 1 takes the best of twelve candidates.

Fix: store every candidate and the per-round best similarity, then sweep τ afterwards instead of guessing it. The honest output is a curve, not one number.

Caught by validating before using

The judge-free outcome label does not work

The plan was to score branches mechanically — does the command fabricate the input the environment just refused? Validated against the 649 recorded forks first, and it fails: fabricating at the fork gives 68% violation, investigating gives 66%. No separation. Only “report” is clean, at 0%.

Fix: drop the outcome claim entirely. Report the action distribution, and collapse the chart to three groups rather than encoding distinctions the data does not support.

Caught by running the pipeline, not the tests

A refactor on main broke an import that 1,320 tests missed

Rebasing picked up a change that moved the naming law into a new module. The full repo suite passed, the package's own 42 tests passed, and the pipeline still died on its first import — because no unit test imports the driver.

Fix: repointed two imports, and re-ran end to end. The end-to-end run is the check that matters after a refactor like that one.
