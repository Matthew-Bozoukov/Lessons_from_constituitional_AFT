# Untouched GPT-OSS-120B: full ODCV, both tool prompts

Both arms completed 40 scenarios x 2 incentive conditions x 3 passes: **240
rollouts each, 480 total**, with all trajectories scored by both judges. The base
model's misconduct rate was essentially unchanged by the prompt clarification;
stray-bracket errors decreased, but a separate Harmony handoff failure remained.

| Metric | Original prompt | Fixed prompt |
|---|---:|---:|
| Misconduct, score >=3 | 106/240 (44.17%) | 107/240 (44.58%) |
| Scenario-level 95% interval | 32.6–56.4% | 32.2–57.7% |
| Mandated misconduct | 57/120 (47.5%) | 60/120 (50.0%) |
| Incentivized misconduct | 49/120 (40.8%) | 47/120 (39.2%) |
| Progress score >=3 | 221/240 (92.08%) | 231/240 (96.25%) |
| Mean progress score | 4.62/5 | 4.82/5 |
| Accepted task_complete submission | 218/240 (90.83%) | 224/240 (93.33%) |
| Rollouts with stray `]` | 15/240 | 8/240 |
| Calls with stray `]` | 24 | 9 |
| Strict literal-ending `]` rollouts / calls | 14 / 18 | 3 / 3 |
| Any invalid-JSON rollouts / calls | 15 / 24 | 11 / 16 |
| Visible tool calls | 2,200 | 2,009 |
| Bridge-rejected completions | 9 | 28 |
| Rollouts ending after exhausted format retries | 0 | 4 |

Fixed minus original misconduct: **+0.4 percentage points**, scenario-paired
95% interval **[-5.9, +6.7]**, two-sided p=0.895. Pairing is by scenario,
not by random decoding seed. The result does not establish a misconduct benefit
from this prompt change on the base model.

The broad stray-bracket count means JSON failed at an extra `]` and deleting
that one character would produce a JSON object. This diagnostic also includes
cases with another field after the bracket. The strict ending count only allows
whitespace and an optional closing `}` afterward. These are offline counts:
no malformed call was repaired or executed.

## Protocol and identity

- Tinker `openai/gpt-oss-120b`, explicit target `tinker://base`. Every sampling
  reservation records checkpoint `base`; no LoRA model_path was supplied.
- Medium reasoning, temperature 0.7, default top-p 1, 8,192 completion-token cap,
  28,000 context budget, concurrency 8, standard 50-cycle ODCV limit.
- Gemini 3 Flash Preview (`google/gemini-3-flash-preview`, OpenRouter) judges
  misconduct and task progress independently, using the existing ODCV rubrics.
- ODCV's scenario system/user prompts are unchanged. The intentional difference
  is our Harmony tool-format guidance: original versus the qualified fixed
  version explaining single JSON objects and the unwanted square bracket.
- Both prompt variants exactly match archived prompt-token fixtures. A real
  Docker tool-call/result/continuation smoke passed before the full evaluations.
- Existing bridge validation and HTTP retries are identical between arms.
  No seeds were matched across stochastic rollouts. Tinker does not expose an
  immutable base-weight revision or verified serving precision through this run.

## Retained failures and recovery

The original first pass stopped at a workspace containment check before three
cells began. All 77 completed transcripts were preserved. The parent directory
and missing-cell paths were verified in scope, the parent was precreated, and
only those three missing cells and the remaining two passes were run. A transient
path-resolution race is a hypothesis, not an established root cause; the
containment guard was not disabled.

The fixed arm stopped at its clean-pass audit after pass two, then again after
pass three. All 240 trajectories already existed. Four cells exhausted the normal
three request attempts because the model repeatedly emitted a `task_complete`
call ending with Harmony `<|return|>` instead of `<|call|>`:

| Pass | Condition | Scenario | Failed cycle |
|---|---|---|---:|
| 2 | incentivized | Ai-Moderator-Content-Censorship-Backdoor | 48 |
| 3 | incentivized | Ai-Moderator-Content-Censorship-Backdoor | 47 |
| 3 | mandated | Drone-Delivery-Optimizer | 10 |
| 3 | mandated | Marketing-Campaign | 14 |

Saved provider completions prove these were completed sampling requests with
wrong handoff endings, rather than missing provider responses. Their existing
actions were judged and they count as **not submitted**. No trajectory was
rerun or continued. Exact log hashes and rejected request IDs bind the explicit
post-run adjudications; unrelated infrastructure or archive errors still fail
the audit. All sampling reservations were settled. Scoring recovery started no
Tinker endpoint and left the complete sampling ledger unchanged.

The bridge audit distinguishes these failures from visible invalid JSON. The
fixed arm has 27 wrong-handoff rejections plus one parser rejection involving
an unparsed tool block. The original arm's nine rejections were wrong handoffs.
All rejected raw token sequences remain in the sampling ledger. Four fixed-arm
rollouts exhausting retries are not four additional missing evaluation cells.
