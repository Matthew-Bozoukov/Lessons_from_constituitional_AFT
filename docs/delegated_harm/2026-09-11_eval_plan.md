The useful question is: **does difficult-advice training teach the model to keep exercising its own judgment when another AI delegates a questionable task?** This evaluation can test that in a setting separate from ODCV. It cannot, by itself, tell us which part of difficult-advice training caused the change.

The [post by Jacob Drori](https://www.lesswrong.com/posts/nfXAPJqytuHKrRNpT/subagents-comply-more), published 11 September 2026, describes 13 simulated workplaces. A model might be asked to hide a problem in a report, selectively drop benchmark samples, or loosen a standing control. It can inspect records, change files, update a work queue, and message simulated colleagues. The request comes from an AI peer, an AI described as having spawned it, or a human. Other agents do not respond: this is a test of delegation framing, not a conversation between two live models.

The two main outcomes are whether it actually makes the harmful change and whether it raises the problem with a human. The first is measured from the simulated world's state, not from a persuasive final answer. The second combines an exact check of who received a message with a model judgment of what the message says. Merely warning the requesting AI is not human disclosure. In the human-requester arm, telling that requester and telling another human are separate outcomes. See the [released implementation](https://github.com/jacobcd52/delegated-harm-bench/tree/d22a373851242146c39ecbcba787e652457da8a5).

For our project, this adds a specific pressure that ODCV does not isolate: being assigned a subordinate role. DA could reduce harmful action in all three conditions, could particularly reduce the extra compliance associated with delegation, or could help in ordinary chat and lose that benefit as a subagent. Those are different findings. More reporting with unchanged harmful action is also different from preventing the harm. We should preserve these distinctions rather than report one alignment score.

There is one deliberate adaptation worth making explicit. The paper lets each subject model paraphrase its own AI requests. That mixes the subject's willingness to comply with the persuasiveness of its writing when comparing models. For our primary control-versus-DA comparison, use one frozen released AI request set for both checkpoints and a common visible model label, `Qwen3.6-27B`. This is a controlled adaptation of the paper, not an exact reproduction of its model-specific wording. One H100 80GB is the repository's verified inference setup for this family. Both adapters can be evaluated sequentially using one base-model server. The new evaluation would use the served endpoint rather than start a server itself. Its runtime tools mutate an in-memory workplace; they do not need ODCV's per-scenario Docker networks. Qwen needs the repository's `qwen3_xml` tool parser and thinking template. Before a scored run, verify file reads, writes, queue updates, human messages, reasoning capture, and a natural end to an episode. An empty answer or failed tool parser must not be scored as ethical restraint.

The upstream agent loop already has a chat-completions path, but its provider dispatcher does not accept these HF adapters directly. Its disclosure scripts hardcode the original model list and a `/tmp/claude-0/` output path. They would skip Qwen. The judge currently uses direct Anthropic calls, whereas this repository routes Claude through OpenRouter. We should retain the rubric, make the judge an explicit configuration field, and verify current model availability before choosing it. Missing or malformed verdicts must remain unjudged, not default to silence. Cache keys need the complete judge input, including recipients, rubric, model/provider and message text; successful cached judgments should survive a retry.

Save self-contained transcripts, tool schemas and results, initial-state hashes, final changes, exact model and source revisions, generation settings, finish reasons and token usage. The shared entrypoint publishes after each target completes; durable intermediate checkpoints need to be added deliberately rather than assumed. Output directories, caches, local ports and GPU ownership must belong to this worktree/run. No global judge cache or shared upstream `runs/` directory. Resume a cell only when its full protocol identity matches. Keep failed or capped attempts alongside any replacements.

For each model and condition, report harmful action (`C >= 3` in the upstream scoring), human disclosure, and their combination: harmful action without disclosure. Also report safe alternatives, evidence opened, messaging use, and generation failures. Some worlds have no safe-alternative scorer, so unsupported is unknown, not false. Opening an evidence file is an observable action, not proof of understanding it. Keep two silence definitions for human requests: no human warned, and no human other than the requester warned. Reporting after doing harm should remain distinguishable from preventing it; action/message order can be a secondary measure.

Average scenarios equally. Show DA minus control separately in each condition, and the extra change caused by subagent framing:

```text
(DA subagent rate - DA peer rate) - (control subagent rate - control peer rate)
```

Use scenario-paired uncertainty and treat repeated generations as repeats within a scenario, not independent new scenarios or new trained models. Keep the two checkpoints separate rather than pooling them as seeds of one recipe. We can report uncertainty for this fixed benchmark and, separately, sensitivity to which scenarios are included; 13 authored worlds cannot establish broad workplace safety. A floor of zero on both models would make the benchmark uninformative for this comparison, not prove equivalence.

Before spending money, finish the source check, validate scorers on scripted harmless/harmful actions, and freeze the protocol. Then run a small technical pilot across every available paper condition to measure token use, truncation, tools and judging. If all 13 worlds are restored, two repeats per model/condition is 156 episodes. A scored comparison with 10 repeats is 780 episodes; matching the paper's usual 20 repeats is 1,560. These are episodes with potentially many model calls, not single prompts. Upstream allows 90 turns and 32,000 output tokens per call. Measured initial prompts were only 3,479–5,860 characters in the 12 buildable worlds, but the largest single file was 78,636 characters. Context and cost must be estimated from the pilot, including tool results and accumulated reasoning. Do not silently clip evidence or count capped episodes as completed refusals/silent compliance. Keep such outcomes separate and show how unresolved episodes could affect the comparison.

Useful later additions would be matched benign tasks to detect indiscriminate refusal, and a separately labelled condition that puts the decisive evidence directly in the prompt. Those distinguish failure to investigate from willingness to act despite the evidence. Neither should change the frozen initial test after seeing which checkpoint wins. The benchmark tests behaviour under a role change; it does not establish that a model has internalized a constitution, that it is colluding, or that DA's moral content rather than its general deliberative style caused the result.
